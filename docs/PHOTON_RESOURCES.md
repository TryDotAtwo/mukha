# Phototransduction resource measurement

Population sizing counted 6091 R1-R6/R7/R8 annotation rows in the accepted MaleCNS candidate index. Seven HBeyelet objects are excluded only from this resource benchmark, not from the complete CNS graph. `reports/photon_resource_population.json` records source hash and type counts. Every diagnostic cell uses the same assumed 30,000 microvilli and alternating dark/light inputs; this is not anatomical visual calibration.

On Molab RTX PRO 6000 Blackwell, the native population allocated 11,706,302,464 bytes (10.902 GiB) of additional VRAM and completed 10 steps at 0.1 ms. Loop wall time was 0.657573299 s; whole process wall time 2.294094002 s. These are startup-state measurements, before a developed light response, not steady-state throughput. The current allocation exceeds the local 8 GiB GPU capacity. Evidence: `reports/molab_photon_resources.json`. The short-run report was exported; the full state artifact was not exported before sandbox loss.

The requested follow-up at 1,000 steps lost its foreground SSE connection after the 10-second heartbeat. The same session endpoint returned HTTP 410. Completion, throughput and cause of loss are unproven (`reports/molab_photon_resource_1000_interruption.json`). Do not retry that expired endpoint or describe the interrupted run as a successful full-scale response.

File checkpoint mode previously allocated three host payload buffers. At this assumed population each buffer is 11,329,747,280 bytes (10.552 GiB), so three buffers alone exceed 31 GiB. The file mode now reuses one buffer for loading, midpoint saving and final-state export. The independent in-memory replay diagnostic retains its three buffers. Windows two-cell fresh-process regression passed both onset cases after this change (`reports/photon_single_buffer_checkpoint.json`); full-population checkpoint I/O and peak host RAM are still unmeasured.

The recovered sandbox also terminated during the 1,000-step retry, after its 70-second heartbeat. A subsequent session discovery returned HTTP 410. No final state or throughput was obtained, and the cause remains unknown. See reports/molab_photon_resource_1000_recovered_interruption.json. A third identical retry was not started. The persistent C ABI described in PHOTON_NATIVE_API.md is now available for integration, but this does not replace the missing full-population result.

## 2026-09-23 throughput diagnosis

A later persistent Molab session completed paired timing runs on the 6091-cell population, with 30,000 microvilli per cell, seed 19503, and 50,000 photons/s. The baseline native library took 6.57168 seconds for 100 steps of 0.1 ms each. This corresponds to about 657 wall seconds per simulated second **for isolated photoreceptors only** at this stimulus and before a long trajectory. The full retina allocated about 10.9 GiB VRAM. Results and benchmark code were SHA-verified in the private HF archive, manifest `manifests/661cc22971e0eec8283742caf46c79bb1d4a04235d82e3e07714673304104842.json` at revision `04aca9da0beac767c8837e024745b3c78e0ec10b`.

Removing per-tick GPU synchronization and host validation in an isolated diagnostic made the 6091-cell run only 1.00234 times faster. This diagnostic is **not adopted** because intermediate invalid states would be detected only after `fp_advance` returns. At 16 cells and 100 steps, its checkpoint payload matched the baseline byte for byte; this is an engineering regression, not a biological pass.

A five-step per-stage diagnostic inserted GPU synchronizations after each kernel. Each full-retina tick spent about 62.9 ms in `transduction`, 0.63 ms in `sum_current`, 0.13 ms in the HH membrane kernel, and less than 0.02 ms in adaptation. The timing includes diagnostic synchronization, so absolute values are approximate, but the ~98% dominance of `transduction` is clear. The source diagnostic is `tools/profile_photon_stages.py`; build ID `436c5d63f56b380cf3de3937f997e920fbb73645a7b7fc3c0b32d5e18e6e396a`.

A second isolated diagnostic precomputed the voltage-dependent exponential once per receptor per tick instead of once per microvillus. It took 6.52223 seconds for the full-retina 100-step case, only 1.00801 times faster than the paired 6.57448-second baseline. The full-retina observed state differed by up to 0.0580 by step 100; a 128-cell 1000-step case differed by up to 0.536. The 16-cell 100-step checkpoint payload was exact. This variant is **not adopted**. Its code, binary, and measurements are in private HF manifest `manifests/4fdf1fb8efea30ec5eaea090bfbdb579249f46ab5a4f8442aa8969226c43757c.json` at revision `8cdaee4123eb9ccb5e15170f00f85f7a863e028e`.

At this isolated photoreceptor rate, a hypothetical 60-second episode would take about 11 hours of continuous GPU time, excluding CNS, body, rendering, KSP, storage, and training. The required 300 held-out landing evaluations alone would take roughly 137 GPU-days if every episode lasted 60 simulated seconds. Actual episodes and throughput can differ; these numbers are an order-of-magnitude planning constraint, not an end-to-end measurement. The current implementation is therefore unsuitable for the planned training campaign. The next candidate must attack the stochastic microvillus algorithm itself or use a biologically validated lower-cost receptor model while preserving the full MaleCNS connectome. Any approximate receptor must be labeled as such, tested against stimulus-response and causal checks, and evaluated with the full model before a biological claim.
