# Полный коннектом: Rust + CUDA, эталон PyTorch

## Принятые требования

- Полный опубликованный коннектом выбранного релиза; никаких отсечений слабых связей, выборки нейронов ради скорости или замены графа искусственной сетью.
- Спайковая симуляция всего выбранного нервного графа. Уравнения Shiu/Eon — исходный ориентир, а не готовое доказательство биологической достоверности на другом наборе данных.
- Rust управляет экспериментом; C++/CUDA выполняет вычисления. PyTorch нужен для простого прототипа, проверки уравнений, градиентов и результатов обучения.
- Основное обучение выполняется в Molab. Локальная RTX 3070 не является целевой машиной обучения.
- Собственный упрощённый симулятор посадки. Положительный результат в нём проверяется отдельно от переноса в KSP.

### Полный исходный граф и модель нейронов — разные объекты

Исходная таблица включает неаннотированные сегменты. Нельзя назвать каждый такой сегмент отдельным установленным нейроном; нельзя и молча удалить их и продолжать называть полученный файл полным исходным графом. Число уникальных сегментов этим аудитом не вычислялось.

Канонический источник хранится целиком. При сборке исполняемого графа нужны явное отображение segment ID → модельная сущность и отчёт о связях на границе идентифицированных нейронов. Отсутствие superclass само по себе не является разрешением удалить узел. Исполняемый граф пока не построен; конкретное разрешение неоднозначных сегментов остаётся задачей следующего этапа.

Нейронные параметры и знаки действия нейромедиаторов не восстанавливаются одной таблицей связей. Сохранять исходные категориальные предсказания, уверенность и происхождение; выбранные физиологические приближения задавать отдельной конфигурацией.

Агрегирование нескольких контактов в вес одного ребра допустимо для модели с одинаковыми задержками и линейно суммируемым воздействием контактов. Если понадобятся отдельные задержки, пластичность или состояния каждого контакта, нужны соответствующие индивидуальные таблицы. Полный взвешенный граф уже скачан; координаты всех синаптических контактов и EM-изображения не скачивались.

## Границы стека

| Компонент | Реализация |
|---|---|
| CLI, схема конфигурации, жизненный цикл эксперимента, запись метрик и checkpoints | Rust |
| Владение GPU-буферами, потоки, CUDA Graphs, библиотечные handles | C++ через узкий C ABI или cxx |
| Обновление нейронов/синапсов, задержки, спайки, физика посадки, native backward и обновления параметров | CUDA/C++ |
| Разреженное распространение активности | Сначала cuSPARSE как библиотечный контроль; собственные ядра по результатам профилирования |
| Компактирование активных событий, сканы, сортировки, редукции | CUB/CCCL либо проверенное специализированное ядро |
| Плотные сенсорные/выходные адаптеры | cuBLAS/cuBLASLt или CUTLASS по фактическим размерам |
| Эталон уравнений и градиентов, первоначальная проверка функции потерь, notebook и визуализация | Python/PyTorch |

Документация библиотечных операций: [cuSPARSE](https://docs.nvidia.com/cuda/cusparse/index.html), [cuBLAS](https://docs.nvidia.com/cuda/cublas/index.html). Версии сборки закрепляются после проверки фактически выданной Molab GPU и toolkit; наличие локального CUDA 12.5 не является проверкой поддержки удалённого Blackwell.

Нативный цикл не вызывает Python на каждом тике. Поток данных: GPU-состояние ракеты → сенсорное кодирование → несколько шагов мозга → моторный декодер → GPU-шаг физики → награда/окончание эпизода. CPU получает агрегированные метрики и checkpoints с заранее определённой периодичностью.

## Представление и вычисления

Исходные ID сохраняются как 64-битные. Компактные индексы графа могут стать 32-битными только после проверки диапазонов. Счётчики и смещения имеют явные проверки переполнения.

Структура графа общая для партии эпизодов; состояние каждой мухи отдельное. Буферы напряжений, синаптических токов, рефрактерности, спайков и физики — плоские SoA-массивы с предварительным выделением памяти. Порядок `[neuron, batch]` — кандидат для совместного чтения одного ребра несколькими потоками по эпизодам; сравнить с альтернативой на целевой GPU. До измерений не объявлять выбранную раскладку оптимальной.

Задержки хранить в предварительно выделенном кольце с индексом текущего слота. Не копировать всю историю при каждом шаге. До замены эталонного сдвига кольцом доказать совпадение порядка чтения/записи, момента срабатывания и reset.

Для первого точного пути: полный обход разреженных связей плюс отдельное обновление состояния нейронов. Сравнивать с распространением только от активных спайков, сохраняя все исходные рёбра и точное действие активного спайка. Изменение порядка суммирования может повлиять на пересечение порога, поэтому одного среднего отклонения напряжения недостаточно.

Произвольный коннектом не удовлетворяет автоматически структурной разреженности Tensor Cores. Прореживание до 2:4 ради матричного ускорения нарушает требование сохранить граф. Плотные подблоки или упаковка могут рассматриваться только с сохранением семантики и с измерением всей стоимости.

## Эталон динамики и обучение

Зафиксировать порядок обновлений и единицы: мембранный потенциал, синаптическое состояние, рефрактерность, задержка, внешний ток/стимул, правило спайка и reset. В [PyTorch-реализации Eon](https://github.com/eonsystemspbc/fly-brain/blob/main/code/run_pytorch.py) используется шаг 0,1 мс и surrogate gradient для спайка; это конкретная модель, которую нужно воспроизвести и проверить до оптимизации.

При прямом сопоставлении нейронного и игрового времени шаг 0,1 мс даёт 500 внутренних обновлений на решение управления при 20 Гц. Менять это соответствие или увеличивать dt ради скорости можно только как явное изменение модели с повторной проверкой.

Начальная проверка — FP32; небольшой CPU-эталон может считать FP64. Сначала сверить один шаг, задержки и короткие траектории с заданной последовательностью стимулов. Затем сверить потери и градиенты на одной и той же surrogate-функции. Численная производная дискретного спайка не является эталоном выбранного surrogate gradient.

Оптимизация forward по активным спайкам не переносится автоматически в backward: у неспайкнувшего нейрона surrogate-производная может быть ненулевой. Нативный backward обязан сохранять те вклады, которые есть в эталоне. Избегать материализации огромного массива `edges × batch × time`; применять ограниченные блоки, накопление градиентов и пересчёт состояний, проверяя результат.

Сохранение всех нейронов и рёбер не означает необходимость одновременно обучать каждый параметр. Начальная фаза может обучать адаптеры и выбранные параметры, затем расширять обучаемую часть. В отчёте всегда указывать, какие параметры менялись. Биологическое локальное обучение и градиентное обучение искусственной динамики — разные эксперименты.

## Критерии перехода к длительному обучению

1. Сверка исходных данных, разрешение отображения сегментов, проверка полноты исполняемого графа.
2. Совпадение PyTorch и native динамики на детерминированных стимулах; отдельная проверка нейронов около порога.
3. Сверка backward и шага обновления параметров, если они переносятся в native.
4. Проверка сохранения/восстановления нейронного состояния, оптимизатора и RNG.
5. Проверка памяти и синхронизации новых CUDA-ядер на целевой GPU, затем измерение unprofiled времени замкнутого цикла.
6. Короткое обучение посадке, отложенные условия и сравнения с необученной сетью; отдельно — перенос в KSP.
